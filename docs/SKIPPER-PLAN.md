# 「姚广孝 · 跳过」开屏跳过器 · 立项计划

> 定位：只管"替你点一下『跳过』"，绝不屏蔽、不注入、不改别人的界面。
> 与 hosts 模块完全解耦：hosts 负责"下载不到"，本 App 负责"下载到了也不让你看"。

---

## 一、市场调查

### 1. 竞品格局

| 产品 | 形态 | 能力 | 现状 |
| --- | --- | --- | --- |
| **李跳跳** | 单机 APK，内置规则 | 开屏跳过，命中率高、无联网 | 2023-08 收律师函后**无限期停更**，商店下架，规则靠社区续命 |
| **GKD** | 开源 APK，无障碍 + 高级选择器 + 订阅规则 | 开屏跳过、弹窗关闭、自定义点击流 | 活跃维护，规则订阅生态最大，规则库上千组 |
| **拦精灵** | 商业 App | 跳过 + 屏蔽 | 2024 被芒果 TV 起诉，一二审均判**不正当竞争**，赔 9 万元 |
| 轻启动 / 一指禅 / 自动跳过 等 | 单机或订阅 | 开屏跳过 | 多数已下架或停更，靠第三方站点分发 |

### 2. 三条关键结论

**结论一：法律风险的分界线在"点"还是"屏蔽"。**
「拦精灵」案的判决说得很清楚：帮用户点"跳过"是正当的；**直接屏蔽开屏广告**才构成不正当竞争。李跳跳栽的也是"屏蔽、过滤浏览器广告"这条指控。
→ 我们的产品红线：**只做点击，不碰渲染、不拦请求、不改布局**。这条也解释了为什么 hosts 模块和跳广告器必须分成两个独立产品，不能对外宣称"一个模块既能屏蔽又能跳"。

**结论二：GKD 赢在"规则是可订阅的文本"，不在技术。**
它把"哪个界面、什么条件、点什么"抽象成规则，社区持续补；李跳跳死在"规则内置在 APK 里，作者一停更就断粮"。我们要么走订阅，要么走"极简规则 + 用户自建"，不能走"内置一大堆规则然后没人维护"。

**结论三：同类产品的下架，主要是商店审核与厂商法务，不是技术被破解。**
无障碍类 App 在国内商店基本进不去（审核直接卡"无障碍 + 自动点击"），这也是为什么这类工具全靠 GitHub / 网盘分发。想"上架商店"这条路本身就不通。

## 二、关于"隐秘一点、别被检测到"

先把话说透：**没有真正的隐身。** 能做的是"降低暴露面"，不是"消失"。而且我不建议往"伪装、对抗检测"的方向做，原因有三：

1. **技术上是军备竞赛，输的是你。** 微信、支付宝、银行、部分游戏会枚举系统里已启用的无障碍服务，见到非系统签名的服务就提示甚至限制功能。你伪装包名、改服务名，对方下一次更新就加签名/行为特征检测，你还得跟着改——这是在给自己挖维护坑。
2. **真正会导致封号的不是"无障碍"，是"自动化产生了收益或伪造了行为"。** 广告主反作弊盯的是"曝光/点击异常"。只要我们的规则**永远只点"跳过/关闭"，绝不点广告主体、绝不点"立即下载/查看详情"**，就不产生任何可被判定为作弊的流量。
3. **对金融、支付、政务类 App 做自动点击，风险不是"封号"级别，是资金安全级别。** 这类直接进"永不启用"名单，宁可少跳几个广告。

### 可以做的"低暴露"设计（合规、可解释）

| 手段 | 效果 | 代价 |
| --- | --- | --- |
| **按包名白名单启用**：只对用户勾选的 App 生效，默认空 | 大部分 App 根本看不到你在用（服务不对其界面动作） | 需要用户先配几个包名 |
| **短时驻留**：只在 Activity 启动后 3 秒内处理窗口事件 | 减少常驻被扫描的概率与耗电 | 复杂的多段开屏可能漏 |
| **无常驻通知 / 无常驻前台服务** | 降低存在感 | 部分 ROM 会杀后台，需引导加白 |
| **不申请联网、不申请 QUERY_ALL_PACKAGES** | 无法上传、无法枚举全量应用，可解释性最强 | 订阅规则只能用户手动导入 |
| **一键关闭 + 全局快捷键**（磁贴/长按） | 用银行、支付前随手关掉 | 需要用户记得 |

### 明确不做的（红线）

- 不伪装成系统服务、不伪造服务标识去绕过别人的检测逻辑；
- 不 Hook 任何 App 的检测函数、不改别人的进程；
- 不自动点击广告内容、不模拟"看完广告"、不做任何能换来收益的点击；
- 不对金融、支付、政务、医疗类 App 启用；
- 不在应用内提供"破解检测"之类的宣传话术——这既是法务风险，也是给用户虚假安全感。

一句话：**我们要的是"用户知道自己在用什么"，不是"让别人不知道"。**

## 三、技术方案

### 架构

```
┌─────────────── App (Kotlin, 无联网) ───────────────┐
│  MainActivity  开关 / 包名白名单 / 命中日志 / 规则导入  │
│  SkipService   AccessibilityService                  │
│    ├─ 事件：TYPE_WINDOW_STATE_CHANGED（主）+ CONTENT_CHANGED（辅）
│    ├─ 闸门：前台包名在白名单内 && 距窗口切换 < 3s && 未冷却
│    ├─ 规则引擎：包名 → 规则组 → 条件（文本/ID/类名/区域）→ 动作（点击节点/坐标）
│    └─ 熔断：同一窗口最多点 2 次、全局每分钟最多 5 次、命中即停
│  RuleStore  本地 JSON（可导入 GKD 风格规则的子集）
└──────────────────────────────────────────────────┘
        ↑ 可选：KSU root 辅助（仅用于"取当前 Activity"，不参与点击）
```

### 规则模型（够用就好，不做万能引擎）

```json
{
  "appId": "com.example.app",
  "name": "示例 App 开屏",
  "rules": [{
    "activity": "*Splash*",
    "delayMs": 600,
    "conditions": [
      {"type": "text", "pattern": "跳过", "region": "top-right"},
      {"type": "text", "pattern": "跳过广告|跳过 {n}s|关闭广告"}
    ],
    "action": {"type": "clickNode"},
    "maxTimes": 1,
    "cooldownMs": 2000
  }]
}
```

要点：

- **文本优先、坐标兜底**：原生 View 能拿到节点就点节点；WebView/自绘界面拿不到节点时才用"右上角区域 + 固定延迟"兜底。
- **只匹配"跳过/关闭"，禁止匹配"详情/下载/领取"**，从规则层杜绝误点广告主体。
- **每次点击都写日志**（时间、包名、命中条件、结果），用户能看见它点了什么——这既是排障手段，也是"可解释性"的证据。

### 与 KSU 模块的关系

- **不做进 hosts 模块**。权限模型不同：一个靠 root 挂载、一个靠无障碍授权；混在一起商店/法务叙述都说不清。
- 可选联动：hosts 模块的 WebUI 里加一行"跳广告器已安装/未安装"的状态，纯展示。

## 四、里程碑与验收

| 阶段 | 内容 | 工期 | 验收 |
| --- | --- | --- | --- |
| **P0 可行性** | 空壳无障碍服务 + 硬编码一条规则（文本含"跳过"+ 右上角），在 3 款 App 上实测 | 1 天 | 能跳 2/3 款；日志能看到命中条件 |
| **P1 规则引擎** | 包名白名单、规则 JSON、延迟/冷却/熔断、命中日志 | 3–4 天 | 10 款 App、跳过成功率 ≥80%，误点 0 |
| **P2 规则生态** | 规则导入（本地文件/剪贴板，不做联网订阅）、内置 10 条示例、规则编辑界面 | 3 天 | 用户能自己加一个 App 的规则 |
| **P3 打磨** | 磁贴开关、耗电优化、HyperOS 保活引导、误点保护 | 2–3 天 | 连续 7 天耗电 < 1%/天 |

**核心指标**：跳过成功率、误点率（必须为 0）、单次启动额外耗电、覆盖 App 数。
**不追求的指标**：支持 App 数量最大化——每多支持一个 App 就多一份维护与误伤成本，宁少勿滥。

## 五、风险清单

| 风险 | 概率 | 应对 |
| --- | --- | --- |
| 商店上架被拒 | 极高 | 不走上架路线，GitHub + 手动安装分发 |
| 厂商法务函（"屏蔽广告"指控） | 中 | 产品只做点击、文档明确"不屏蔽"，hosts 与 skipper 分开交付 |
| App 检测无障碍后限制功能 | 中 | 白名单默认空、一键关闭、金融类永不启用 |
| 规则误点广告主体 | 中 | 条件层仅允许"跳过/关闭"语义，坐标兜底限定右上角 20% 区域 |
| 自绘界面拿不到节点 | 高 | 坐标兜底 + 单 App 定制，不追求全覆盖 |
| 后台被杀 | 高 | 引导加白 + 磁贴快捷开关，不做激进保活对抗 |

## 六、下一步

先做 **P0**：一个只有一条规则的最小 APK，装到你机器上跑三个 App，用日志证明"能被无障碍读到节点、能点中、不会点错"。跑通了再谈规则引擎——P0 失败（比如自绘界面占比太高），整个方案就要换路线（回到 root 截图识别）。
